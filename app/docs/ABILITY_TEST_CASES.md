# Ability Test Cases — Combat Rewrite Validation

> **Status:** Reference archive. Not a spec, not a ship list, not a roadmap.
> **Purpose:** Preserve the 20 hypothetical abilities generated across 4 test rounds during the combat rewrite design phase (2026-04-12). Each ability is a probe — if the rewritten architecture cannot cleanly express any of these, that's a gap worth investigating before or during implementation.
> **Produced during:** Combat rewrite design phase, parallel with `COMBAT_REWRITE_DECISIONS.md` and `COMBAT_REWRITE_PLAN.md`.
> **Role:** Generated by executor sessions acting as ability generator. Scoring done by orchestrator sessions.

## How to read this doc

- Abilities listed here are **test cases**, NOT features slated for implementation.
- If the rewritten architecture handles all 20 without new primitives, the architecture is pulling its weight.
- If most land in 8-10/10 but one scores 3/10 with "impossible/out of scope" framing, that's a **committed boundary** worth documenting (see Butterfly Effect).
- Rounds 1-2 have orchestrator scoring. Rounds 3-4 have executor-private axis predictions, pending orchestrator scoring.
- Each behavior is self-contained and copy-pasteable — new sessions can drop any ability into a fresh scoring exercise without context loss.

## Round 1 — Generic complex

**Dimension:** Broad complexity probe with no specific axis. The goal was to establish whether the new architecture genuinely compresses ability complexity, or whether the 5-layer spec was just prettier rewrite of the same pain.

**Outcome:** Four abilities scored 8-10/10 with ~4× LOC compression on average (660 → 165 LOC total). One ability (Time Loop) scored 6/10 — tractable but still hard. The orchestrator flagged the 6/10 as the honest ceiling for the architecture.

### 1.1 Execute

Deals 2× damage to targets under 25% HP. On kill, refunds its own cooldown and grants 2 stacks of `Bloodlust` (+10% next-attack damage per stack, consumed on use).

- **Axis:** Conditional damage modifier, kill trigger, self-state mutation (cooldown), charge-based buff with consume-on-use semantics, stack tracking
- **Scoring:** ~60 LOC → ~15 LOC | medium-hard → easy | **8/10**

### 1.2 Soul Link

Target ally shares 30% of incoming damage with caster for 5 seconds. If caster dies while linked, ally gains `Enraged` (+50% atkRate, 3s). If ally dies first, caster gains a shield equal to ally's max HP for 5s.

- **Axis:** Damage redirection/splitting, two conditional death outcomes, cross-unit state tracking across lifetimes, temporary shield, buff lifecycle with multiple end conditions
- **Scoring:** ~120 LOC → ~25 LOC | very hard → easy | **10/10**

### 1.3 Toxin → Plague

Applies `Toxin`; each DOT tick adds +1 stack (max 5). At 5 stacks, converts to `Plague`: spreads 3 stacks to all enemies within 40px, resets source to 1 stack, but tick damage +50%. Plague cannot revert to Toxin.

- **Axis:** Stacking DOT with tick-driven accumulation, threshold transform, AOE spread on state transition, per-stack tick damage, effect type conversion
- **Scoring:** ~80 LOC → ~20 LOC | hard → easy | **9/10**

### 1.4 Time Loop

On cast, snapshots target's position, HP, atk, effects, and cooldowns. After 3s, rewinds target to the snapshot (even if it died in the interval). All damage dealt during the 3s is then reapplied as "pure" damage that bypasses armor, shields, resistances, and `modifyDamage` hooks.

- **Axis:** State snapshot/restore across full unit lifecycle, dead-unit resurrection, delayed effect, bypass-ALL-modifiers damage channel, queued damage accumulation
- **Scoring:** ~300+ LOC → ~80 LOC | effectively impossible → hard but tractable | **6/10**
- **Note:** The honest Round 1 ceiling. The 6/10 is correct — state snapshot + resurrection + bypass-all-modifiers is intrinsically hard, not an architecture failure.

### 1.5 Chain Reaction

Primary hit deals X damage. If target has `Burn`, detonate it: AOE equal to 2× remaining burn damage, consumes the burn. Second trigger: spread the original burn at 50% duration to the 3 nearest enemies. Chain recurses once more if any of those 3 already had burn.

- **Axis:** Effect consumption, conditional cascading logic with depth limit, damage-type interaction (burn → AOE), effect transformation/copy with modified parameters, recursion guard
- **Scoring:** ~100 LOC → ~25 LOC | hard → easy | **9/10**

## Round 2 — Harder than Time Loop

**Dimension:** Deliberately push past the Round 1 ceiling. Each ability was designed to stress architectural dimensions Round 1 didn't touch (world rollback, ability-as-data, telemetry, hook transferability, deferred resolution).

**Outcome:** One committed exclusion (Butterfly Effect at 3/10 — world rollback is out of scope for combat layer, requires separate Replay Engine). Four at 8-9/10 but **three demanded 1-2 new primitives each**, surfacing 4 architectural gaps that were subsequently baked into `COMBAT_REWRITE_DECISIONS.md`.

**Gaps surfaced by Round 2 (now part of Doc 1):**

1. **WorldEntity layer** (biggest finding) — non-unit things (Pylons, Projectiles, Zones, Pickups, Trail segments) want shared lifetime/spatial/targeting infrastructure. Added as Layer 0.5 via ECS-lite components-as-data.
2. **Resources as a primitive** — charges, mana, ammo, rage. Added as Layer 6.
3. **Pending events first-class** — delayed/groupable/cancellable events. Added as Phase 5 deliverable.
4. **Persistent vs battle-scope state** — two-tier unit state for data that survives pool recycle and identity changes.

### 2.1 Butterfly Effect

When this unit dies, rolls back the last 2 seconds of combat for all units within 200px — positions, HP, effects, cooldowns, and in-flight attacks all revert. Then the fight replays from that point with this unit at 1 HP. Damage dealt by this unit during the replay is permanent; all other state changes from the replay also commit (different units may now live or die than in the original timeline).

- **Axis:** World-level state rollback, multi-unit resurrection, cascading replay with divergent timeline, deterministic re-simulation
- **Scoring:** Impossible → Impossible | **3/10**
- **Status:** **COMMITTED EXCLUSION.** World rollback requires deterministic simulation spanning AI, movement, RNG, particles — none of which live in the combat layer. No combat rewrite will enable this class of ability. If ever pursued, it's a separate "Replay Engine" workstream. See `COMBAT_REWRITE_PLAN.md` out-of-scope list.

### 2.2 Mimicry

Copies the next ability cast by any unit within 200px — permanently gains it as its own (same cooldown, same targeting) for the rest of the battle. Copied abilities use THIS unit's stats, not the original caster's. If the copied ability is itself Mimicry, this unit instead steals the target's already-copied ability. Each unit can only be mimicked once per battle.

- **Axis:** Ability-as-first-class-data, runtime ability reference swap, recursion guard on meta-ability, stat-vs-ability decoupling, per-unit "has been mimicked" persistent state
- **Scoring:** ~150 LOC partial rewrite → ~30 LOC | **9/10**
- **Validates:** Layer 3 data-oriented ability model (the cleanest win in Round 2)

### 2.3 Probability Well

Creates a 150px zone for 8 seconds. Inside the zone, all damage dealt, healing received, and effect durations applied to a unit are replaced by that unit's rolling 5-second average of the same metric. A unit with no history uses the action's literal value. If the zone expires mid-swing, pending foreswings resolve with whichever formula was active at foreswing START, not at damage-land time.

- **Axis:** Zone-based effect modification, rolling per-unit history buffer, statistical replacement of values, foreswing-snapshot timing capture
- **Scoring:** Hard → ~150 LOC + **2 new primitives** | **8/10**
- **New primitives needed:** rolling history buffer per unit, zone-scoped damage/effect override

### 2.4 Soul Graft

Target ally permanently gains a copy of this unit's `onDeath` hook in addition to its own. When this unit dies, it also fires the grafted ally's `onDeath` once. If chained deaths happen (an `onDeath` kills a Soul Graft holder, whose `onDeath` kills another, etc.), the cascade runs depth-first with cycle detection and a max depth of 5. Graft survives the caster's pool recycle.

- **Axis:** Death-as-data (hooks as transferable), cascade safety with depth limit, persistent state across pool recycle
- **Scoring:** Hard + fragile recycle → ~80 LOC + **1 new concept** | **8/10**
- **New concept needed:** persistent unit state layer (battle-scope vs recycle-scope split)

### 2.5 Quantum Strike

Launches an attack that exists in two states simultaneously: melee (40 dmg, no knockback) and ranged (25 dmg, 50% crit, 30 knockForce). The target shows both outcomes as pending. Collapse triggers on first of: (a) target takes damage from another source, (b) target moves > 20px, (c) 1.5s elapse. On collapse, the system picks whichever outcome is most favorable to the caster's side right now and applies it retroactively, firing the full hook chain as if it had always been that outcome.

- **Axis:** Delayed multi-outcome resolution, observer-collapse with multiple trigger conditions, retroactive application of full damage chain, dual-state pending events
- **Scoring:** Hard + breaks invariants → ~100 LOC + **1 new concept** | **8/10**
- **New concept needed:** pending events as first-class primitive (queryable, groupable, cancellable)

## Round 3 — World-state persistence

**Dimension:** Permanent alteration of the battle environment. Each ability must persist after the casting unit dies and specify its own cleanup rules. Designed to stress-test the WorldEntity hypothesis from Round 2.

**Status:** Pending orchestrator scoring. Executor axis predictions included below, to be compared against orchestrator results.

**Executor signal prediction (pre-scoring):** Gravity Well and Corpse Garden should land 5-8/10 with 1-2 new primitives each (projectile-as-entity, occupancy-based lifetime). Soul Pylon is the forcing function for whether Modifiers (Layer 5) can target WorldEntities. If the architecture can't express these cleanly even with WorldEntity added, the layer is underspecified.

### 3.1 Salt Field

On death, the caster's corpse transforms a 60px radius around its position into a salt field. Any unit moving through it takes 5 DPS and has `healing received` reduced by 30%. The field persists until the battle ends, OR until a unit with the `Cleanse` passive walks through it (consuming that unit's cleanse charge). Two overlapping fields stack DPS additively; healing reduction caps at −50% regardless of overlap count.

- **Axis probed:** terrain-as-entity with decay, death-triggered creation, modifier interaction with healing, stacking with per-property caps, caster-less lifetime

### 3.2 Soul Pylon

Summons a 200 HP immobile pylon at the caster's position. The pylon has its own HP bar, its own resistance table, its own position, and its own `onDeath` hook — it is a targetable entity that enters the damage pipeline when attacked, but has no movement, no attack, and no capacity cost. While the pylon stands, any ally that dies within 150px is queued to revive at 30% HP at the pylon's location after 3 seconds. The revive is a cancellable pending event: if the pylon dies before the 3s elapse, the revive is cancelled and the ally stays dead.

- **Axis probed:** structure-entity with full combat lifecycle, cap-counting exemption, pending revive events tied to a non-unit, cross-lifetime dependency (revive cancels on pylon death)
- **Forcing function:** does Layer 5 (Modifiers) target WorldEntities or only Units? If yes → Pylon can be buffed/debuffed by existing auras. If no → Pylons bypass the modifier system entirely.

### 3.3 Scent Trail

Wherever this unit walks, it drops a trail segment every frame. Each segment records `(x, y, timestamp, ownerSide)` and decays over 10 seconds. Allied units within 20px of a fresh segment (age < 5s) gain `+20% speed`; enemy units get `−20% speed`. Segments older than 10s are removed from the spatial index. If the caster dies, its existing segments decay at **3× normal rate** but do not immediately vanish.

- **Axis probed:** append-only spatial entity set, query-time modifier derivation, per-entity decay rate change on posthumous trigger, scales to thousands of entities per battle

### 3.4 Gravity Well

Creates a 50px radius gravity well at a target point for 8 seconds. Projectiles from both sides that cross into the well are pulled toward its center. Projectiles that impact inside the well deal damage to all units inside the well, not just the direct target. Persists past the caster's death. Two overlapping wells merge: their centers converge at the midpoint, combined duration capped at 15s.

- **Axis probed:** projectile-as-first-class-entity (promotes ranged attacks from events to entities with trajectory), entity-to-entity interaction, merging entities on overlap, zone AOE from external trigger

### 3.5 Corpse Garden

When this unit dies (only way to create), spawns a 100px radius garden at the death location. Any unit that dies inside the garden expands its radius by 20px in the direction of the kill, capped at 300px. Enemies standing inside take `−10% atk rate` and apply a `rot stack` on any unit they attack (1 per hit, max 5, each stack reduces target's healing by 5%). The garden persists until no units have been standing in it for 5 continuous seconds.

- **Axis probed:** self-modifying terrain boundary, death events from other units as growth triggers, occupancy-based lifetime (not duration-based), per-unit rot stacks persisting after leaving the garden

## Round 4 — Cross-ability interaction

**Dimension:** Ability A modifies how Ability B works. Each ability probes a different way abilities can reach into each other's pipelines — this is the core stress test for the phase-subscription model before Phase 3 (abilities) lands.

**Status:** Pending orchestrator scoring. Executor axis predictions included below.

**Executor signal prediction (pre-scoring):** If the phase-subscription model is complete, most should land 7-9/10 with existing primitives. If the model is missing "next X" interception (Doubled Intention) or battle-scope global state (Reality Strike), those score lower. Reality Strike is the most likely candidate for "cleanly out of scope" — the architecture's state model is entity-centric, not battle-scope-centric.

### 4.1 Prismatic Aegis

When this unit would take damage, the incoming damage's type is converted to whichever of `[heat, cold, electric, void]` the target is currently MOST resistant to. The conversion happens BEFORE resistance lookup, so the target benefits from its highest-tier resistance regardless of the actual attack type. Lasts 6 seconds. Applies to direct damage only, not to DOT ticks. If a Prismatic Aegis is already active on a target, reapplying refreshes duration but does not stack the conversion effect. Effects attached to the original attack follow the converted type, not the original.

- **Axis probed:** mid-pipeline mutation of `event.dmgType`, phase-subscription ordering (must run before `resist` but read `target.resistance`), effect propagation to mutated damage type

### 4.2 Doubled Intention

Curse effect applied to a target. Remains dormant until the next time the target is hit by a CC effect (stun, slow, freeze, fear). When triggered, the incoming CC is applied twice as two independent instances, each using the original caster's tier stats. The curse then expires. If two Doubled Intentions are active on the same target, the next incoming CC triggers both curses: four independent CC instances apply.

- **Axis probed:** "next X" stateful interception (the effect system currently has `onApply`, but does it support "when ANOTHER effect is applied to me, intercept"?), multi-curse composition semantics, deterministic interception ordering

### 4.3 Plague Amp

Aura within 80px of the caster. While inside the aura, any toxic DOT applied to a unit gains `+100% tick damage` AND `+50% to the effect's max-stack cap`. When a unit carrying an amplified plague stack leaves the aura, existing stacks retain their boosted tick damage, but the max-stack cap reverts to the effect's default — excess stacks are dropped oldest-first. New stacks applied outside the aura use default values. Two overlapping Plague Amps multiply the tick bonus (×4) but share a single max-stack cap ceiling at `+75%`.

- **Axis probed:** cross-ability modifier on effect APPLICATION (not damage), position-dependent modification, retain-vs-revert asymmetry on source removal, per-effect-property lifecycle semantics, multi-source multiplicative/additive/capped mixing

### 4.4 Syphon Link

Tags a target with a soul link to the caster. For the next 8 seconds: (a) any heal received by the caster is also applied at 50% strength to the linked target, and (b) any damage the caster deals to the linked target applies an additional 25% of that damage as lifesteal on top of the caster's normal damage calculation. Link breaks early if either unit dies. If the caster is healed by an aura affecting multiple allies, the 50% replication fires once per heal event received, not once per ally in the aura.

- **Axis probed:** cross-unit event subscription from non-source position (caster subscribes to heals targeting itself), compound modifiers (damage + bonus lifesteal), event-count vs target-count semantics, paired-entity lifecycle

### 4.5 Reality Strike

Immediate cast. At the moment of casting, scans all active status effects across the entire battlefield and identifies the most common effect type (burn, poison, stun, slow — whichever single effect has the most active instances). For the next 4 seconds, that specific effect type cannot be applied to any unit by any ability. Existing instances of the banned effect continue ticking and expiring normally. During the ban, abilities that would have applied the banned effect deal their damage as normal but skip the effect application entirely. If two Reality Strikes are cast within each other's 4s window, they may ban different effect types simultaneously.

- **Axis probed:** battle-scope global state (not per-unit, not per-zone), effect-type blacklisting at the effect system level, "would have applied but silenced" semantics, state orthogonal to entity lifecycle
- **Note:** Most likely candidate in Round 4 for "cleanly out of scope" — the architecture's state model assumes state lives on entities. Global state is currently not a primitive.

## Uncovered dimensions (future rounds)

From the original 10-prompt surgical list. Probe these if the rewrite design surfaces ambiguities in any of these areas or the orchestrator wants another validation round.

- **Resource economy** — charges, mana, ammo, rage, momentum, blood pacts. Partially addressed by Layer 6 in Doc 1, but not directly probed.
- **Cooperative / multi-unit** — channels, chain attacks requiring formation, relay buffs, sacrifice rituals, formation triggers.
- **Information / visibility** — stealth, fake positions, revealed intent, misreported HP, wrong-target curses. Currently scoped outside combat (AI plan territory), but the boundary is worth mapping.
- **Non-combat integration** — abilities that interact with nectar economy, wave scaling, lane-bound passives, run-persistent traits, incubation-scaled damage.
- **Self-referential / recursive** — scales with own cast count, reads combat event log, immune to self, chain-detection on own ability.
- **Anti-pattern / spec-breaker** — attacker retargeting mid-attack, retroactive damage changes, both-sides unit, parallel pipeline, deck-dependent effects.

2. Generate 5 abilities that each probe a different facet of that dimension.
3. Use the per-ability format: name, behavior (copy-pasteable), axis probed, scoring (or executor hypothesis if pre-scoring).
4. Update the rounds overview table.
5. Update the summary table.
6. If orchestrator scoring happens later, backfill the pending entries and note any new gaps surfaced.
